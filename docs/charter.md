# 宪章

## 1. 目标

**最终目标**：所有者的财务自由与被动收入。

**系统目标**（能被检验的那部分）：在任何情形下都不承担归零风险的前提下，找到扣除成本之后真实存在的优势，并且知道它能容纳多少资金。

优先级：先求不死，再求结论正确，最后才是收益高低。

## 2. 三条底层约束

所有设计都从这三条推出来。它们不是偏好，是算术。

### 2.1 统计：证据要用时间或广度去换

t 统计量 ≈ 年化夏普 × √年数。要有 80% 的把握在 U1 的确认集（639 天，1.75 年）上得到 t ≥ 3，年化夏普至少要约 **2.90**；即使按有机制的例外降到 t ≥ 2.5，也要约 2.53。反过来，一个年化夏普 1.0 的真实优势，要约 **14.8 年**的数据才有同样的把握。命令：`uv run sqp power --days 639`。

推论：
- 单一品种的择时信号，几乎不可能只靠确认集被证实。能把夏普推到这个量级的只有**广度**：大量同时进行、彼此独立的下注（主动管理基本定律：信息比率 ≈ 单次预测质量 × √独立下注数）。
- 所以研究优先选广度大的问题（横截面、多品种），并且每个假说注册前先过功效检验：事先认为合理的效应低于门槛，就不浪费确认集，改等前向数据或扩大宇宙。

### 2.2 多重检验：试得越多，噪声越像优势

每次都没有真实优势、一共试了 N 次时，最好那一次的年化夏普预期值（Bailey 与 López de Prado，2014）：

| 试验次数 | 1.75 年样本 | 5 年样本 |
|---|---|---|
| 10 | 1.19 | 0.70 |
| 100 | 1.91 | 1.13 |
| 1,000 | 2.46 | 1.46 |

计数是**跨代累计**的。第二代已经在加密市场计入 9 次试验、在传统市场计入 10 次（`registry/inherited/trials.json`），换一个仓库不会让这些次数清零。

### 2.3 容量：小资金唯一的结构性优势

机构不做的地方，往往是因为太小、太碎、不值得做。这正是小资金能赚钱的地方，也意味着优势一放大就消失。所以每个结论都要回答"在多少资金以内成立"。系统不预设本金，由模型输出最佳资金区间（[决策 0009](decisions/0009-one-model-capital-range.md)）。

## 3. 原则

第 1–14 条继承自第二代 finance-research 的宪章，原样保留；第 15–18 条是第三代新增的。

| # | 原则 | 含义 |
|---|---|---|
| 1 | 结论是产品 | 每项研究的终点是一条带不确定度的结论，回测曲线只是证据之一 |
| 2 | 先有机制，再看数据 | 说不出"谁在付钱、为什么会一直付"的信号可以研究，但按探索性对待，门槛更高。数据越多，这条约束越松 |
| 3 | 先登记，再检验 | 检验方案在看结果之前冻结；每次试验自动记入只增不改的账本 |
| 4 | 只用当时能知道的信息 | 数据按"何时可知"查询，前视在接口层面无法表达 |
| 5 | 留出数据是消耗品 | 最后一段数据封存，访问需要批准并永久记录 |
| 6 | 先算成本和容量 | 不扣成本的优势不算优势；每个结论都注明能容纳多少资金 |
| 7 | 先求不死，再求增长 | 仓位按"优势估计可能有错"来定，任何情形下不承担归零的风险 |
| 8 | 陌生人能重算 | 任何一个数字，都能由一条命令从原始数据重新算出，结果一致 |
| 9 | 简单优先 | 每增加一个参数或一层复杂度，都要有样本外的收益来证明它值得 |
| 10 | 失败的结果同样入库 | 被否定的假说永久保留，它们是试验计数的一部分，也防止重复劳动 |
| 11 | 停止条件事先写好 | 一个策略进入模拟盘之前，先写明什么情况下判定它已失效 |
| 12 | 提出者和审查者分开 | 结论发布前，由没有参与过这项研究的会话专门寻找反例和更简单的解释 |
| 13 | 一个模型 | 研究产出信号，所有信号进入同一个模型；信号的价值是它对整体的边际贡献，不是它单独的回测 |
| 14 | 结论有适用范围 | 每个结论登记它被验证过的市场、周期和条件；用到范围之外等于提出新假说 |
| 15 | 跨代记账 | 前代的试验计入试验次数；前代看过的数据，对同一族假说不再算"没见过" |
| 16 | 规则即代码 | 能被检查的规则一律写成检查，由持续集成执行；不能检查的写进 PR 模板，由人确认 |
| 17 | 资金区间是输出 | 不预设本金；模型输出净收益最好的资金区间，以及优势消失的资金上限 |
| 18 | 生产与实验分开 | 谷歌云只跑已验收的生产任务；实验全部在免费环境里做 |

## 4. 不做什么

继承第二代：
- 毫秒级高频：可以研究，但不建设对应的交易设施，除非研究证明扣掉我们真实的手续费、延迟和排队劣势之后仍然赚钱（[决策 0028](decisions/0028-prepare-second-universe.md)）。个人在速度、托管设施和融资成本上没有优势；分钟到数天的周期在范围之内。
- 不依赖法律、税务或监管上的漏洞。
- 不预测点位。系统测量条件概率和效应大小，不回答"明天涨还是跌"。
- 不追求数量。一条 E4 结论胜过一百条 E1 结论。

第三代新增：
- 任何阶段都不写提币和资金划转代码。
- 不让语言模型做交易决定，也不让它当闸门。闸门是确定性的代码。
- 不付费买信号、课程或"内部消息"。
- 在法律条件满足之前，不碰别人的钱（G8）。
- 不把 WorldQuant BRAIN 的任何内容带进本仓库。

## 5. 合理预期

（继承第二代）严格的检验下，多数假说会被否定。已有文献也是这样：公开发表的股票异象里，约三分之二在更严格的复现中不再显著（Hou、Xue 与 Zhang，2020）；即使成立的，发表之后收益平均下降约 58%（McLean 与 Pontiff，2016）。

所以这个系统最可能带来的三种价值，按确定性从高到低：

1. **避免把钱投给不成立的策略。** 几乎必然实现，而且价值最大。
2. **正确的仓位和配置。** 即使没有任何超额收益，在既定风险约束下把低成本的市场收益拿足，本身就是一个可解的优化问题。
3. **少数几个幅度不大、但真实的优势。** 来自机构因规模或约束而不做的地方。不保证出现。

第三代补一句：G1–G4 的大部分产出会是"否定"。这不是失败，是系统在工作。按 2.1 节的功效计算，第一个能进模拟盘（E4）的信号，最可能来自广度大的横截面研究，而不是单一品种的择时。

## 6. 事前验尸

假设一年后第三代失败了，最可能的原因和对策：

| # | 最可能的失败原因 | 对策 |
|---|---|---|
| 1 | 骨架太重，研究还没开始精力就耗完了（第二代卡在 Phase 2 的数据平台） | G0 只放能被检查的规则；每个阶段有时间盒和砍掉条件；G2 起必须有真实研究在跑 |
| 2 | 换代悄悄重置了试验计数，用看过的数据"重新发现"了噪声 | 跨代记账和暴露声明，由检查强制；前向数据优先 |
| 3 | Claude 订阅到期后，接手的模型不守规则或读不懂上下文 | 规则写成代码；AGENTS.md 是唯一规则源；交接记录；闸门从 `main` 运行，PR 改不了 |
| 4 | 谷歌云账单失控 | 每月 10 美元预算：按量服务（G5 起的 Cloud Run 等）用封顶预算到顶即停；存储不受封顶预算控制，靠数据量小、代码限量和预算提醒（决策 0015）；只部署生产任务（[成本护栏](cost-guardrails.md)） |

**最强的反方意见**：不该开新仓库，应该继续 finance-research。它已经有规程、注册表和一部分数据层；新仓库会重复劳动、推迟研究。

第三代的回应：只继承不可再生的东西，代码按需重写；用"迁移验收"证明确实超越（[代际传承](lineage.md) 第 4 节）；G1 的数据层从头写，只参考第二代的设计，不等 finance-research 的去留（决策 0015）。如果到 G2 结束时，第三代还没有比第二代多出可检验的能力，这条反方意见就成立，应当回到第二代。
