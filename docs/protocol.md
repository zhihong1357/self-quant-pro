# 科研规程

底本是第二代 finance-research 的科研规程。继承的部分保留原意，第三代新增或改动的地方标注"（第三代）"。阈值的数值在 `config/protocol.toml`，两处不一致时以那里为准。

## 1. 一项研究的生命周期

想法 → 假说卡（草稿）→ 探索集上打磨 → 功效检验 → 注册（冻结检验方案）→ 确认检验（只做一次）→ 结论 → 进入模型的准入检验 → 前向数据 → 模拟盘 → 所有者考虑实盘

## 2. 研究宇宙与分段

每个研究宇宙在第一次用于研究之前，按时间切成四段，写进 `registry/universes/`，之后永远不动：

| 段 | 用途 |
|---|---|
| 探索集 | 提出和打磨假说，随便看 |
| 确认集 | 每个已注册的假说只检验一次 |
| 金库 | 最终检验，需要所有者批准（`registry/ledger/approvals.jsonl`） |
| 前向 | 边界定下之后才产生的数据，证据效力最高 |

U1 的边界继承自第二代：探索 2019-12-01 至 2024-01-31，确认 2024-02-01 至 2025-10-31，金库 2025-11-01 至 2026-10-31，前向 2026-11-01 起。重新切分等于再掷一次骰子，所以不允许。

**数据层怎么执行（第三代）。** 研究读数据的唯一入口是时点接口（`src/sqp/data/pit.py`），它只返回指定时刻之前已经可知的行。规则如下（[决策 0020](decisions/0020-point-in-time-interface.md)）：
- 一行数据属于它变得可知的那一段。
- 读确认集和前向数据，要有本研究宇宙已经注册的假说（状态是 registered 或 confirmed），而且只能在 GitHub Actions 的 main 上运行；读金库，还要所有者的批准记录：`{"type": "vault", "universe": "U1", "hypothesis": "H-NNNN"}`。
- 分段、注册和批准都以合并进 `main` 为准。
- 硬边界是存储桶的凭据：智能体的环境里没有，所有者也不要把自己的谷歌云登录交给智能体（[决策 0022](decisions/0022-pit-hardening-after-review.md)）。
- 被拒绝的请求写进 `refusals.jsonl`。

**暴露（第三代）。** "没见过的数据"是对一族假说而言的。任何一代的任何一次试验只要在某段数据上算出过绩效，这段数据对这族假说就"用掉了"。用掉的情况写在研究宇宙文件的 `[exposure]` 里，`sqp check` 对照继承记录核对，不许漏报，可以多报。对已用掉的族，确认集和金库只能当探索集用，证据只能来自 `burned_through` 之后的前向数据。U1 目前有 5 个族的确认集和金库都已用掉（[决策 0008](decisions/0008-cross-generation-accounting.md)）。只用掉了金库的族写在 `vault_burned` 里：确认集照常可用，最终检验改用前向数据；资金费率族就是这种情况（[决策 0013](decisions/0013-u1-exposure-by-evidence.md)）。声明时可以按最坏情况多报；要撤销已声明的暴露，必须用决策记录逐项写明实际用过的数据。

**文献暴露（第三代）。** 已发表的研究如果报告过同一策略在确认集时段的表现，这个检验就不是盲的：这个假说不用确认集，改用前向数据，或者改成文献没覆盖的版本（[决策 0014](decisions/0014-published-results-count-as-exposure.md)）。

**模型暴露（第三代）。** 预训练语言模型训练时见过的文本，可能含有比被打分的数据更晚的信息。所以由这类模型生成的特征（情绪打分、结构化抽取、文本向量），在模型知识截止日之前的数据上都算已暴露：确认检验只能用截止日之后的数据，或者每个时点只用在该时点之前训练的"时序一致"模型。注册时写明模型、版本和知识截止日，原始输出按输入的指纹缓存进私有存储桶（[决策 0016](decisions/0016-model-knowledge-counts-as-exposure.md)）。

研究者对市场的一般印象（比如知道 2024 年大涨过）无法从脑子里删掉。分段防的是"对着数据调参数"，防不了常识。所以机制必须事先说清楚，不能事后编。

## 3. 假说卡与注册

假说卡放在 `registry/hypotheses/H-NNNN.toml`，格式见 [模板](templates/hypothesis.toml)。字段沿用第二代的设计：机制、谁在付钱、为什么会持续、为什么轮到我们、可证伪条件、先验。

**注册前的功效检验（第三代）。** 注册时写下事先认为合理的最小效应 `min_effect_sharpe`，再用 `uv run sqp power --days <确认集天数> --trials <累计试验次数>` 算出门槛。合理效应低于门槛时，不注册确认检验，改为：用前向数据检验、合进整体模型、扩大宇宙（增加广度），或者把想法留在探索阶段。用前向数据检验之前，同样要过这一关，`--days` 用计划的前向长度（[决策 0030](decisions/0030-h0009-waits-for-the-model.md)）。

**注册前查文献。** 注册时在 `literature_exposure` 写明查过哪些文献、有没有覆盖确认集时段（决策 0014）。没写不能注册。

**注册后冻结。** 除 `status`、`status_history` 外全部冻结；阈值只能比默认更严；t 统计量门槛只有写明机制理由（`mechanism_exception`）才能从 3 降到 2.5。这些都由 `sqp check` 执行。

## 4. 证据等级

| 等级 | 条件 | 可以用来做什么 |
|---|---|---|
| E0 | 只有想法和机制 | 写假说卡 |
| E1 | 在探索集上成立。单独回测最高只能到这一级 | 继续研究 |
| E2 | 在确认集上，对整体模型的边际贡献显著，且通过多重检验折损 | 作为信号进入模型，标注"初步" |
| E3 | 在另一个研究宇宙或另一段时期复现，且机制的其他推论也成立；附容量曲线（第三代） | 作为信号进入模型 |
| E4 | 注册之后的前向数据上成立，长度不短于注册时算好的最短长度 | 可以进入模拟盘 |
| E5 | 模拟盘的表现落在预期分布之内 | 可以提交所有者考虑实盘 |

"机制的其他推论"是指：如果机制是真的，除了被检验的现象，还应当看到别的现象。例如做市商对冲真的放大波动，那么效应应当在期权到期日前后更强。检验推论比反复检验同一个现象更有说服力。

## 5. 默认阈值

| 检验 | 默认 | 说明 |
|---|---|---|
| t 统计量 | ≥ 3 | 有明确机制的，注册时写明理由可降到 2.5 |
| 折损夏普 | ≥ 0.95 | 按同一研究宇宙的全部试验折损，含继承的试验 |
| 回测过拟合概率 | ≤ 0.10 | 只适用于从多组参数里选优 |
| 成本加倍 | 仍为正 | — |
| 去掉最好的 2 笔 | 仍为正 | — |
| 参数扰动 | 上下 20% 内符号不变 | 结论不依赖某个精确的参数值 |
| 分段 | 多数子时期方向一致 | — |

这些是暂行值。G3 的元研究把整条流程放在纯噪声上跑，量出实际误报率，再定稿（改 `config/protocol.toml` 需要决策记录）。

## 6. 试验记账

**什么算一次试验**：任何一次在真实数据上运行、并输出绩效或显著性指标的计算。

**什么不算**：结果指纹完全相同的重复运行；在合成数据上的运行；不输出绩效指标的数据检查。

**计数范围**：同一研究宇宙的全部试验，包括已被否定的假说。100 个假说各试一次再挑最好的，和一个假说试 100 次是同一回事。彼此高度相关的试验按"有效独立试验次数"计，估计方法在 G3 定下。

**跨代计数（第三代）**：继承的试验按领域计入，数字在 `registry/inherited/trials.json` 的 `counted_by_domain`：目前加密 9 次、传统市场 10 次（mixed 同时计入两边）。折损用的试验次数 = 继承的 + 本代的。

**怎么记（第三代）**：先登记，后运行（[决策 0025](decisions/0025-trials-registered-before-they-run.md)）。每次试验先在 `registry/ledger/trials.jsonl` 追加一张试验卡（假说编号、研究代码、数据段、参数、一句理由；动用金库时引用批准记录的 `seq`），所有者合并之后，运行框架才在 GitHub Actions 的 main 上跑它，每张卡只跑一次。卡一合并就计数，开始以后崩溃的也算；为了核对可重现而登记的重跑也计数（多报可以，漏报不行）。代码提交、数据和结果的指纹写在存储桶的 `ledger/trials/` 下，运行日志也打印这些指纹。

**数值放在哪里（第三代）**：由第三方数据算出的指标、报告、预测都放在私有的谷歌云存储桶里，按指纹和账本对应；公开账本里不出现这些数值（[决策 0011](decisions/0011-derived-results-stay-private.md)，`derived-results` 检查执行）。

**被拒绝的请求也要记**：时点接口拒绝的每一次请求写进 `refusals.jsonl`。它们没拿到数据，不算试验，但所有者应当看得到有人（或有代码）试过越界。

**为什么先登记**：靠自觉记的账，漏掉的恰恰是结果不好、被随手丢掉的尝试，而它们正是折损计算最需要的。先登记，结果出来之前账就记下了，想漏也漏不掉。

## 7. 信号准入

所有研究的产出都是信号，所有信号进入同一个模型（[决策 0009](decisions/0009-one-model-capital-range.md)）。

- **准入检验**：在相同数据和约束下，分别运行包含和不包含这个信号的整体模型，比较扣成本后的样本外表现。方法和阈值在注册时冻结，并记下当时作为基准的模型版本。
- **单独回测**只用于诊断信号本身是否合理，最高支撑 E1。单独亏钱的信号，仍可能因为与其他信号互补而通过准入。
- **适用范围**：每个信号登记它被验证过的研究宇宙、预测周期和市场条件。用到范围之外，等于提出新假说。
- **预测波动而不是方向的信号**进入风险模型，准入比较加入前后整体组合的风险调整后表现。
- **模型本身的修改**走同样的流程：新旧版本在同一份数据上比较，修改计入试验账本。
- **退役**：已进入模型的信号持续监控边际贡献，越过事先设定的界限即移出，并在结论里记录。

## 8. 成本与容量（第三代）

E3 及以上的结论必须附：

1. **成本假设**：手续费档位、买卖价差、市场冲击（随成交量占比增长）、资金费率或借贷成本。
2. **容量曲线**：在一组资金规模上（例如 1 千、1 万、10 万、100 万美元），扣成本后的年化收益和夏普。
3. **最佳资金区间**：净夏普最高的那一段。
4. **容量上限**：净夏普降到 E2 门槛一半时的资金规模。
5. **成本加倍**后的同一条曲线。

## 9. 标准报告

每份报告包含以下章节，缺一项即视为未完成。G2 起由运行框架生成，存放在私有存储桶里，公开仓库只记报告的指纹。

1. 结论：一段话，含效应方向、大小和不确定度
2. 假说与机制：引用假说卡
3. 数据：来源、时间范围、分段、已知缺陷、暴露情况
4. 方法：与注册方案的任何偏离都要列出并说明原因
5. 结果：效应量、置信区间、累计试验次数（含继承）、折损后的显著性
6. 边际贡献：加入整体模型前后的对比
7. 成本与容量（E3 起）
8. 稳健性：成本加倍、去掉最好的 2 笔、参数扰动、分段
9. 适用范围与停止条件

## 10. 从研究到实盘

E4 进入模拟盘，E5 提交所有者考虑实盘。实盘还要满足 [决策 0005](decisions/0005-live-trading-gate.md) 的全部条件，并完成 [合规](compliance.md) 的核对。
