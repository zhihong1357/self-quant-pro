# 0011 由第三方数据算出的数值不进公开仓库

- 状态：已接受（第 4 条推迟到 G7 之前，"尽早开始采集"作废，见 0012）
- 日期：2026-11-24
- 提出：Claude（G0 合并后核对数据条款时发现的遗漏）

## 背景

第二代 finance-research 的决策 0008 已经定过这条规则，第三代在 G0 里漏掉了：G0 把 myquant 的完整试验记录（包括指标）原样复制进了本仓库，而本仓库是公开的。

2026-11-24 核对的 Binance Vision 数据条款（Vision Dataset Terms 1.0，2026-08-26 更新，叠加 CC BY-NC-SA 4.0）：

- 允许纯个人、非生产用途的历史回测研究（第 4.1 条）。
- 不得把数据用于实盘的自营交易（第 4.2 条）；由数据得出的图表、模型、指标受同样的条款约束（第 2.4 条）。
- 再发布派生作品必须注明来源，并以同样的 CC BY-NC-SA 4.0 许可发布（第 4.5 条）。本仓库没有附开源许可，所以不能放这类派生结果。
- 商业许可需要另签企业数据协议（第 3.4 条）。

第二代还记下了另外两家的条款（2026-11-13 读过，本次没有重新核对）：Deribit 的市场数据和派生数据只限个人使用、未经许可不得发布；Cboe 网站内容只供个人非商业使用。

## 决定

1. 由第三方数据算出的数值（试验指标、数据画像、研究报告、模型预测）不进公开仓库，存放在私有的谷歌云存储桶里（决策 0010）。公开仓库只放代码、规程、合成数据上的结果，以及私有结果的指纹。
2. `sqp check` 新增规则 `derived-results`：`registry/` 下的 JSONL 记录，顶层不允许出现 metrics、result、returns、pnl、predictions 等字段。配置写在 config/governance.toml。
3. 继承记录改为只复制标识、日期、状态和指纹，不复制结果：修改 config/inheritance.toml，用新规则重新生成 registry/inherited/。原始记录仍可按指纹到前代的公开仓库核对。
4. 实盘的数据来源（G7 进入条件的一部分）：用 Binance Vision 研究出来的模型，不能直接用于实盘。G7 之前要二选一：取得 Binance 的企业数据许可；或者只用条款允许自营交易的数据（例如交易所接口按时采集的前向数据）重新估计和验证模型。哪一条可行，G1 登记数据源时逐个核对。

## 后果

- G2 的运行框架：试验账本只写指纹，数值结果写进私有存储桶，按指纹对应。
- 研究阶段（G1–G4）可以照常用 Binance Vision 的数据，这属于条款允许的个人非生产研究。
- 从交易所接口采集前向数据，既是 E4 的证据，也可能是将来实盘合规的数据来源，所以应当尽早开始（G1 评估）。
- G0 那次提交的历史里仍有完整的试验记录。它们本来就公开在 myquant 自己的公开仓库里；改写 `main` 的历史违反分支规则，也会让账本引用的提交消失，所以不改写，只从当前版本里去掉。
