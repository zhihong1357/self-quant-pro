# 0013 U1 的暴露声明按实际看过的数据修正

- 状态：已接受
- 日期：2026-11-24
- 提出：Claude（做研究可行性地图时，逐个核对 myquant 的两项探索实际用过哪些数据）

## 背景

决策 0008 把 7 个假说族的确认集和金库都算作已用掉。其中 2 个族没有试验记录，是按最坏情况算的：微观结构（myquant 的 microstructure-4a、4b）和资金费率（myquant 的 funding-history）。2026-11-24 核对了它们实际用过的数据：

| 探索 | 用了什么数据 | 算了什么 | 碰到 U1 的哪一段 |
|---|---|---|---|
| microstructure-4a、4b | OKX 的 BTC 永续，2026-11-18 两个小时的逐笔成交，加十分钟盘口 | 校验成交模拟，没有信号，没有绩效 | 都没碰到（金库在 2026-10-31 结束） |
| funding-history | OKX 的 BTC、ETH、SOL 永续，2026-08-17 至 2026-11-18 的已结算资金费率 | 描述统计（均值、极值、正负次数），没有预测检验 | 金库的 2026-08-17 至 10-31；确认集没碰到 |
| portfolio-5a | 同上的资金费率窗口，加 2026-10-01 起的 OKX 日线 | 校验账户计算，结论里不含绩效 | 同上 |

OKX 不在 U1 里，但各家交易所的资金费率高度相关，所以按"看过"算。

## 决定

1. 修改 registry/universes/U1.toml：
   - 从 `families_burned`（确认集和金库都用掉）里去掉 `crypto.microstructure` 和 `crypto.funding`。
   - 新增 `vault_burned = ["crypto.funding"]`：资金费率族的确认集可以用；金库对这个族不再算没见过的数据，最终检验改用前向数据。
2. `crypto.funding` 指所有用资金费率当信号的假说，包括资金费率 carry 和结算前后的价格压力。
3. 其余 5 个族不变。
4. 以后的规则：声明暴露时可以按最坏情况多报；要撤销已经声明的暴露，必须像本决策这样，逐项写明实际用过的数据（日期、品种、算了什么）。

## 后果

- 资金费率 carry 现在就能用确认集检验，不需要等前向数据。这正是研究可行性地图排在第一位的假说族。
- 微观结构族在 U1 上没有暴露，但宪章已经排除毫秒级交易，它在地图上的优先级仍然很低。
