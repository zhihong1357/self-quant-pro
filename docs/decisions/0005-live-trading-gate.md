# 0005 实盘闸门

- 状态：已接受
- 日期：2026-11-24
- 提出：所有者（"实盘部分会在这个范围里面，但也都是最后最后，全部确定能赚钱后再考虑"；进入条件"沿用"第二代）

## 背景

第二代的立场是：证据等级到 E5、所有者明确决定、数据条款允许，才谈实盘。第三代沿用，并把能写成检查的部分写成检查。

## 决定

1. G7 之前仓库里不得有任何下单代码；任何阶段都不得有提币和资金划转代码。由 `sqp check` 的代码扫描执行。
2. 进入 G7 的条件，全部满足：
   - 至少一个信号达到 E5；
   - 所有者在 `registry/ledger/approvals.jsonl` 里的批准记录，经所有者合并生效；
   - 不爆仓约束：最坏情形（含跳空、交易所停摆）下，单个账户的损失不超过所有者事先写下的上限；
   - 合规核对的六件事全部完成（`docs/compliance.md` 第 2 节），包括交易场所对所有者当时居住地合法开放、数据条款允许实盘；
   - 交易所密钥只开交易权限、关闭提币、绑定 IP 白名单、存放在 Secret Manager；
   - 熔断：日内亏损、对账不符、数据中断任一触发，立即停止下单并通知所有者。
3. 小额起步，按容量曲线和实盘表现逐级加资金。每加一级都是一份新的决策记录。

## 后果

- 在 G7 之前，任何"先接上交易所试试"的代码都会被持续集成拦下。
- 即使到了 G7，资金也不能经由代码转出账户。
