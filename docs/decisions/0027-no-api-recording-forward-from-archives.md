# 0027 不从 Binance 交易接口录数据；前向数据先用公开归档的月度文件；实盘的交易场所和数据到 G7 之前一起定

- 状态：已接受
- 日期：2026-11-26
- 提出：Claude（Opus 5.5），做完决策 0026 第 5 条要求的条款核对之后提出。所有者合并即批准

## 背景

决策 0026 第 5 条要求：A 和 B 选完之后、G2 结束之前，核对 Binance 接口数据的条款，每天录资金费率和 K 线，再注册 2 到 3 个只靠前向数据检验的假说。理由有两个：前向证据要从注册那天才开始算；实盘能用的数据（决策 0011 第 4 条）只能从开始录的那天攒起。

A 和 B 已经各估计过一次（运行 45765535965）：T-0004（A）和 T-0005（B）都判"不通过"。按决策 0026，两个都不花确认集，改等前向数据。

2026-11-26 核对了以下条款（这不是法律意见）：

| 文件 | 版本 | 和本项目有关的条文 |
|---|---|---|
| Binance 用户条款 | 生效日 2026-10-27 | 第 2.1 条：使用者不能位于禁止国家名单上的地区，也不能位于使用 Binance 服务违法的地区；第 14.1.2 条：接口另有接口条款，并且要经过 Binance 同意；第 27 条：许可只限非商业的个人使用或内部业务使用；第 33.7 条：条款预期用户会用 Binance 的技术搭建自动交易系统，后果由用户自己承担 |
| 禁止国家名单 | 2026-01-05 版 | 第 1 组：美国（人在美国，或者是美国居民、美国公民，都不行）；第 2 组：加拿大、荷兰；第 3 组：古巴、朝鲜、伊朗，以及几个受制裁的地区 |
| Vision 数据条款 | 1.0，2026-08-26 更新 | 第 2.3 条：任何个人或机构都可以免费使用；第 4.1 条：允许纯个人、非生产用途的历史回测；第 4.2 条：不得用于实盘自营交易（决策 0011 已经记下） |

由此得出三点：

1. **GitHub 的服务器上录不了。** 我们的定时任务跑在 GitHub 的服务器上。这些服务器在美国，而美国在禁止名单的第 1 组；Binance 的主接口本来也拒绝来自美国的访问（[代际传承](../lineage.md)第 6 节）。
2. **换个地方录，价值也不大。** 从接口录下来的数据，只对"在 Binance 上实盘"有用。能不能在 Binance 上实盘，要看所有者到那时住在哪里、在当地是否合法（[合规](../compliance.md)第 2 节第 1 项）。所有者现在居住地的核对结果属于个人信息，不写进公开仓库，已经直接告诉了所有者；结论是现在还定不下来。另外，还在交易的合约，它们的 K 线和资金费率历史，以后随时可以从接口补下载（Binance 接口文档，置信度高）。补不回来的只有已经下架的合约，以及一些只能当时看到的数据。
3. **前向证据不需要自己录。** 前向检验只要求所用的数据在注册之后才产生。公开数据站每月发布的新文件，每周的同步工作流已经在自动存进来（[决策 0018](0018-mirror-binance-vision.md)），比实际时间晚约一个月，不影响证据。这就是[决策 0012](0012-no-self-collection-on-critical-path.md) 第 2 条的做法。

考虑过的做法：

| 做法 | 要做什么 | 风险 |
|---|---|---|
| 在 GitHub 的服务器上直接录 | 新增一个每日工作流 | 会被拒绝；就算连得上，也违反用户条款第 2.1 条 |
| 在所有者的电脑上每天录 | 电脑一直开着；电脑上放一个能写存储桶的凭据；要有人维护 | 凭据放在家用电脑上不安全；电脑一关数据就断；录下的数据可能根本用不上（见上面第 2 点） |
| 在谷歌云上换个区域录 | G5 之前就开谷歌云的计算（规则 10 不允许）；新建部署流程 | 工作量大；同样可能用不上 |
| 改录别的交易场所的数据 | 先选定交易场所 | 交易场所还没定，现在选只能靠猜 |
| **不录；前向数据用公开归档；交易场所和实盘数据到 G7 之前一起定（采用）** | 不新增任何任务 | 如果到时选了 Binance，已下架合约的接口历史补不回来（它们仍可以用公开归档来研究，只是不能用于实盘） |

这个选择最弱的假设是"到时选的交易场所不是 Binance"。即使到时选了 Binance，损失也有限：还在交易的合约可以补下载；研究结论本身也可以继续用公开归档复核。

## 决定

1. **不从 Binance 的交易接口录数据。** 决策 0026 第 5 条里"每天录资金费率和 K 线"这一项作废；同一条里"注册 2 到 3 个只靠前向数据检验的假说"照常做。
2. **前向数据就是公开归档在注册日之后新发布的部分**（决策 0012 第 2 条），先只用月度文件。路线图 G2 里的"每日前向数据"（决策 0023）移到 G5：G5 的每日影子运行本来就要逐日数据，到时和生产计算放在哪个区域一起定。第一个只靠前向数据检验的假说，现在就可以注册。
3. **实盘用哪个交易场所、用什么数据，到 G7 之前一起定**（决策 0011 第 4 条；合规第 2 节第 1、3 项）。所有者的居住地变了，或者交易场所的牌照情况变了，都要重新核对。
4. 合规表里加上 Binance 用户条款这一行。

## 后果

- 不新增每日工作流，也不改动任何冻结文件。定时运行偶尔没有触发（交接记录 2026-11-26）不会影响前向数据。
- 前向检验看到新数据要晚约一个月。前向证据要积累 2 到 3 年（[研究地图](../research-map.md)第 2.1 节），晚一个月不影响结论。
- G5 多一项交付：公开归档的逐日文件。
- 如果到 G7 选了 Binance，已下架合约的接口历史会缺一段。到时再评估补救办法，例如购买数据。
