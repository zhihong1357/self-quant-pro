# 0021 探索集画像：只描述、只读探索集、一条命令能重算

- 状态：已接受
- 日期：2026-11-25
- 提出：Claude，所有者合并即批准

## 背景

G1 的最后一条验收标准是"U1 探索集的数据画像能一条命令重算"。画像要回答的问题见研究可行性地图第 4 节：

- 资金费率的分布；
- 持续性：这一期高，下一期还高吗；
- 按合约规模和流动性分组，有什么差异；
- 2022 年熊市里是什么样子。

数据已经齐了：全部归档已存（决策 0018），已整理成月度表（决策 0019），研究只能经过时点接口来读（决策 0020）。

## 决定

1. **命令和工作流。** 命令是 `sqp data profile`；工作流 `.github/workflows/profile.yml` 只能手动触发。
2. **只读探索集。** 通过时点接口读，截止时刻是确认集开始前的最后一刻，所以确认集、金库和前向数据一行也读不到。
3. **只描述，不算收益。** 画像里没有任何收益，也没有任何"信号和后来收益之间关系"的统计量，所以按规程第 6 节，跑画像不算试验，不计入试验次数。内容如下：
   - **覆盖**：起止月份，每月有多少个合约。
   - **资金费率的分布**，分全部、每年两种口径：
     - 每次结算费率的均值、标准差、分位数；
     - 年化的均值和中位数；
     - 为正的比例；恰好等于默认费率 0.01% 的比例；单次绝对值不小于 0.1% 的"极端"比例。
   - **按流动性三等分**：每个月按此前 30 天的日均成交额分组，只用当时已经知道的数据。成交额只是规模的近似，我们的数据里没有市值，也没有持仓量。
   - **持续性**：
     - 自相关，间隔 1、3、9 次结算；
     - 截面五分位：同一时刻至少 20 个合约时排五档，看下一次结算还留在同一档的概率。
   - **2022 年熊市**：同样的分布，以及流动性三等分。
4. **结果放哪里。** 画像只写进私有存储桶：

   ```
   derived/profiles/U1-exploration/code-<代码提交>-inputs-<输入指纹>.json
   ```

   旁边另有同名的 `.md`，是给人看的中文摘要。日志只打印对象名和指纹，不打印任何数字。
5. **能重算，而且结果一样。**
   - 报告里不写运行时间；键排序；数字保留 6 位有效数字。
   - 同样的代码、同样的输入，第二次运行会算出指纹完全相同的报告，程序会报告"重算一致"；如果不一样，运行失败。
   - 输入指纹由读过的分块名单算出。存储桶里的对象只增不改，所以名单相同，内容就相同。
6. **怎么看结果。** 所有者从谷歌云控制台下载 `.md`，发给智能体解读。在对话里给智能体看，不算发布；仓库里只记对象名和指纹。

## 后果

- G1 的三条验收标准都有了落实。合并后由智能体连续触发两次画像：第一次写入，第二次应当报告"重算一致"。之后可以提议 G1 验收，进入 G2；阶段变化要另开决策。
- 数字的解读（例如 A、B 两个候选的探索集估计）属于 G2，按研究可行性地图里的规则来做。
- 本 PR 同时更新：路线图 G1 一节、架构第 2 节、所有者简报（怎么下载画像）、交接记录。
