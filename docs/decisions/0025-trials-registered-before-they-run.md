# 0025 试验先在仓库登记、所有者合并后才能跑；每张试验卡只跑一次

- 状态：已接受
- 日期：2026-11-25
- 提出：Claude（Opus 5.5）。所有者 2026-11-25 选定方案 D（加上打印指纹的补救）和"开始读数据后崩溃也算一次"，合并即批准

## 背景

规程第 6 节原来写的是：G2 起由运行框架把每次试验自动写进 `registry/ledger/trials.jsonl`。可是真实数据的试验只能在 GitHub Actions 的 main 上跑（只有那里有存储桶的凭据，决策 0022），而 main 有保护，GitHub 不能直接往里写。要让 GitHub 跑完再写回仓库，就得让它自动开 PR：要么打开"允许 Actions 开 PR"的设置、每次再点一次批准（`gate` 会不会照常运行，查不到确切说法），要么给它一把能写仓库的新令牌。

## 选项

| 方案 | 做法 | 代价 |
|---|---|---|
| A | 先跑后记：跑完由 GitHub 自动开入账 PR | 每次试验批准一次、合并一次；`gate` 可能不运行 |
| B | 同 A，但用所有者新建的可写令牌开 PR | 多一把以所有者身份写仓库的令牌 |
| C | 只写存储桶，智能体下次会话补记 | 补记靠人，和"不靠人工"冲突 |
| **D** | **先登记后跑：试验卡先合并进 main，GitHub 只跑登记过的卡，结果只进存储桶** | 登记了但没跑成的卡也计数；临时想多试一组参数要再登记一次 |

## 决定

1. **采用方案 D。** 每次试验在 `registry/ledger/trials.jsonl` 追加一张试验卡（`type` 为 `trial`，写明假说、研究代码、数据段、参数和一句理由；格式见 `src/sqp/research/trials.py`），经 PR 由所有者合并。试验编号由账本的 `seq` 决定：`seq` 为 7 就是 T-0007。几次试验可以在同一个 PR 里登记。
2. **试验次数按登记算。** 一张卡合并进 main 就计一次，跑没跑、跑没跑完都算（多报可以，漏报不行）。不计的只有两种：合成数据上的试验，以及声明为重跑（`repeat_of`）、并且输入和结果的指纹与原试验一致的试验。重跑的指纹对不上时，运行报警，下一个 PR 追加一条更正，把它计入。
3. **每张卡只跑一次。** 运行框架在读任何数据之前，先在存储桶里写一个不能覆盖的标记 `ledger/trials/<编号>.started.json`；确认检验还要先写 `ledger/confirmations/<研究宇宙>/<假说>.json`。第二次运行（包括 GitHub 的"重跑"）写不进标记，读数据之前就被拒绝。开始以后崩溃的运行留下标记，算一次试验（所有者 2026-11-25 的决定）；想再试，就登记一张新卡。
4. **探索集的试验拿不到确认集。** 数据段为 exploration 的卡，运行时不带假说编号，时点接口因此拒绝探索集以外的一切，即使假说已经注册。
5. **结果只进存储桶，日志打印指纹（补救）。** 指标写进 `derived/trials/<编号>/result.json`，标准报告写进 `derived/trials/<编号>/report.md`，各自的指纹写进 `ledger/trials/<编号>.completed.json`。运行日志打印这些对象名和指纹，不打印数字。日志是公开的，任何人都能拿指纹和存储桶里的文件核对。出错时只打印错误的类型和代码位置，不打印错误信息，因为错误信息里可能带着数字。
6. **`sqp check` 新增 `trial-card` 规则**，检查每张卡都跑得起来：字段齐全；研究代码和假说卡存在；合成数据的假说只用 synthetic 段；确认集、金库、前向只给已注册、注册时计划用这一段的假说；每个假说只有一张确认检验的卡；金库要引用所有者批准记录的 `seq`；重跑必须和原试验完全相同，而且不能用在确认集、金库、前向上。
7. 新增工作流 `.github/workflows/trial.yml`：手动触发时可以写一个试验编号，不写就跑所有还没开始的卡；每天 01:23 UTC 也自动跑一次。和其他读存储桶的工作流一样，只在 main 上、由定时或手动触发时才拿得到凭据。
8. 规程第 6 节"怎么记"一段相应改写。

## 后果

- 先登记后跑，结果还没出来，试验就已经记在公开的仓库里，不好看的结果没法悄悄不记。这比"跑完再记"更严。
- 仓库里看得到登记了哪些试验，看不到结果；结果和指纹在存储桶里，所有者从控制台下载。
- 每次试验多一步：登记、合并、等运行。所有者不在时，最晚第二天的定时运行会跑。
- 研究代码在 `src/sqp/research/studies/` 里，受 `research-boundary` 检查（PR #16）。
- 以后如果试验多到一张张登记太慢（例如 G3 在纯噪声上跑上百次的元研究），再考虑一次登记一批参数的格式；那种试验用合成数据，本来就不计数。
