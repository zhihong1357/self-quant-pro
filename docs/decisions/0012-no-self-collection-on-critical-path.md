# 0012 研究的关键路径不依赖自己采集的数据

- 状态：已接受
- 日期：2026-11-24
- 提出：所有者（"那么目前就不用于实盘，尽量避开因为要自己采集而导致项目需要等待卡死的情况"）

## 背景

决策 0011 发现 Binance Vision 的数据不能用于实盘，并建议尽早从交易所接口自己采集数据，为将来的实盘做准备。

自己采集有两个代价：数据只能随日历时间一天天积累，不能补采过去；采集任务要一直维护，一断就留下缺口。如果研究要等它，项目就会卡住。

所有者决定：目前不做实盘；研究不要因为等自采数据而停下来。

## 决定

1. 目前不做实盘。G7 留在路线图的最后，不作计划。
2. G1–G6 的研究和证据只用公开归档：可以一次下载全部历史，而且每天继续发布新数据（例如 Binance Vision 的逐日文件）。前向数据（E4）就是这些归档在注册日之后新发布的部分，不需要自己采集。
3. 不新增自采任务。第一代已经在跑的录制任务（期权快照、GEX 等）照常在后台运行，但任何研究结论都不以它们为前提。
4. 决策 0011 第 4 条（实盘用的数据从哪里来）推迟到 G7 之前再解决。0011 后果里"应当尽早开始采集（G1 评估）"作废。
5. 唯一无法避免的等待，是统计上需要的时间：确认集和金库已经用掉的假说族，证据只能来自注册之后的前向数据。这部分放在后台积累，不挡主线；主线优先研究确认集还没用过的假说族（见[研究可行性地图](../research-map.md)）。

## 后果

- G1 不需要所有者维护任何新的采集任务。
- G5 的前向影子运行只做预测、不下单，按研究用途理解 Binance Vision 的条款（置信度中）。G5 开始前重新核对条款。
- 将来如果要实盘，要先解决数据许可（0011）。到那时可能要补采或购买数据，实盘因此会晚一些开始。
