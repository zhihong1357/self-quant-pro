# 0001 新仓库建第三代，只继承三样不可再生的东西

- 状态：已接受
- 日期：2026-11-24
- 提出：Claude（Opus 5.5），依据所有者 2026-11-24 的要求

## 背景

前两代：myquant（TypeScript，13 项研究、20 条试验记录）和 finance-research（Python，严格的科研规程，停在 Phase 2）。所有者要求每一代"迭代整合、借鉴效仿并超越"，在空仓库 self-quant-pro 开始第三代。

换代有三个风险：试验计数被悄悄清零；看过的数据被当成新数据；第二系统效应（新系统想一次做完所有事，越做越重）。

## 决定

1. 第三代在 self-quant-pro 从零搭建。前两代只作参考，不搬代码；需要的实现按本仓库的约定重写，并配上测试。
2. 只继承三样不可再生的东西：试验记录（`registry/inherited/`）、数据的分段边界（`registry/universes/U1.toml`）、没被看过的数据（暴露声明，见 0008）。
3. 继承的内容按固定提交生成（finance-research `a7683918e28b`、myquant `feb6a07b7a03`），`sqp inherit verify` 可以逐字节核对。
4. "超越"按迁移验收定义：重现、补上前代没有的能力、复杂度预算（`docs/lineage.md` 第 4 节）。

## 后果

- 前两代的仓库保持原样，本仓库不修改它们。
- finance-research 的后续由所有者约 2026-12-08 决定；如果决定继续，G1 可以接管它的数据代码（重写并配测试）。
- 如果到 G2 结束，第三代还没有比第二代多出可检验的能力，就应当回到第二代（宪章第 6 节）。
